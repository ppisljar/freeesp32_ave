Techniques beyond the four modalities

Binaural, monaural, isochronic and photic are the four ways to carry a rhythm, and each has its own page. This page is everything else the firmware can do with them: how to make flicker that drives the retina without being seen, how to give each eye its own frequency, how to stop a response adapting away, and six more. None of these are modes you switch on — every one is a pattern of ordinary columns.

Everything on this page is implemented and reachable from a session file today. Where a technique is only partly supported, or where the obvious way to write it does not do what it looks like it does, that is called out in the section itself. Techniques that were researched but not built are listed at the end under What is not implemented, so you do not go looking for a column that was never added.

Antiphase “invisible” flicker

The problem with photic entrainment is that it is unpleasant. A bank of LEDs strobing at 40 Hz in front of closed eyes drives the retina well and feels like being inside a fault. The way out is to split the field into two banks of complementary colour and run them exactly half a cycle apart. Each bank is flickering at full depth, so the retina still receives a 40 Hz oscillation in both colour channels — but the sum of the two banks is almost constant, so the overall brightness of the field barely moves and the flicker largely disappears from conscious view.

This works on this firmware because the LED carrier shapes are luminance-linear: no perceptual gamma is applied on the way out, specifically so that a 180°-antiphase pair of raised sines sums to a constant rather than to a residual ripple. That is a deliberate property of the flicker engine, not a happy accident.

Writing it

Two LED lines at the same timestamp, on disjoint masks, with complementary colour and a 180° difference in the phase column. Use env 1 (raised sine): square edges cannot sum flat.

# time freq duty bright  R   G   B  mask env phase
# amber bank, zones 1-2
0      40   50   60    255 150  40   3   1    0
# cyan bank, zones 3-4, half a cycle later
0      40   50   60     40 170 255  12   1  180

The two lines must share a timestamp. LED phase is applied at use-time from the live period, so it stays a fixed phase relationship through a frequency ramp — but only if both channels were anchored together. Start them a few hundred milliseconds apart and you get the phase difference you asked for plus whatever the start offset happened to be.

Brightness-match the two banks by eye at the colours you actually chose. The sum is flat only if the two banks are equally bright; an amber bank at 60 % against a cyan bank at 40 % leaves a 20 % ripple at the flicker rate, which is visible and defeats the point.

EEG-contour carrier

Wave type 7 is not a geometric waveform. It is a single-cycle lookup table shaped like a recorded EEG trace — the “replicated EEG waveform” of Monroe US 5,213,562 — and its harmonic series is fixed by the table rather than by a formula:

Measured harmonic amplitudes, 200 Hz carrier, 10 s capture.
h1h2h3h4h5h6
1.0000.5000.3310.2210.1400.091

It is a carrier, not a noise type, and it needs a real frequency. Two places in the code are careful about that: the test that waives the frequency check for noise is a range test over wave types 4–6 written specifically so 7 falls outside it, and the carrier scaling likewise leaves 7 unscaled. The practical consequence is that an EEG channel is about 6 dB hotter than a noise channel at the same vol. Budget for that when you mix one in.

# A time freq pan vol mod ch freqR waveType
A   0   200   0  55   0   1   206       7

Its binaural beat comes from left/right detune exactly like a sine's, because both ears read the same table at their own phase. The line above is a 6 Hz binaural beat on an EEG-contour carrier.

AM noise

Gating a broadband noise source at the target rate drives a much wider swathe of the cochlea than a single tone does, and is markedly less fatiguing over a long session — which is why it is the usual choice for sleep work, where a pure tone becomes irritating long before the session ends.

Wave types 4, 5 and 6 are white, pink and brown noise, measured at +0.05 dB/oct, −3.04 dB/oct and −6.07 dB/oct respectively over 60 Hz–3 kHz. These are the only wave types for which freq 0 is meaningful — a noise generator has no pitch to set.

# A time freq pan vol mod ch freqR wave duty env phase attack jitter depth
A   0     0   0  60 2.0  3     0    5   50   3     0      4      0    90

That is pink noise gated at 2 Hz with a trapezoid envelope, a 4 ms edge and 90 % depth — a delta-band sleep bed. Noise channels sit 6 dB below tone channels by design, so vol runs higher than you would use for a sine.

Split-field, a frequency per eye

Because the LED mask selects which zones a line drives, and because the glasses build puts separate zones in front of each eye, two LED lines at the same timestamp can run the two eyes at different rates. The optic chiasm sends each hemifield predominantly to the opposite hemisphere, which is the mechanism the split-field patents (Siever, US 5,709,645) are built on.

# time freq duty bright  R   G  B  mask env
# left eye (zones 1-2) at 16 Hz
0      16   50   55    255 120 0    3   1
# right eye (zones 3-4) at 6 Hz
0       6   50   55    255 120 0   12   1

Which physical LED sits in which zone is a wiring decision — see LED topology and per-eye masks for the mapping on both builds. Mask bit 0 is LED 1, so the left eye above is bits 0–1 (3) and the right is bits 2–3 (12).

Different frequencies work today; phase-locked same-frequency split-field also works, using the phase column exactly as the antiphase section does. What you cannot do is give the two eyes different colours of the same flicker on the direct-PWM backend, which has no per-pixel colour at all.

Traveling-wave phase gradients

Give each of N zones a phase of 360°·k/N and the field stops being a set of zones flashing together and becomes a wave moving across it. At around 10 Hz this interacts with the visual system's own spatial dynamics and is the usual route to the rotating, mandala-like closed-eye form constants.

Eight zones, 45° apart:

# time freq duty bright  R   G   B  mask env phase
0      10   50   50    180  80 255    1   1   315
0      10   50   50    180  80 255    2   1   270
0      10   50   50    180  80 255    4   1   225
0      10   50   50    180  80 255    8   1   180
0      10   50   50    180  80 255   16   1   135
0      10   50   50    180  80 255   32   1    90
0      10   50   50    180  80 255   64   1    45
0      10   50   50    180  80 255  128   1     0

Note the descending phase column. phase is a lead, not a lag: the firmware adds phase × period / 360 to elapsed time, so a larger number makes the edge arrive earlier. To make the wave travel from zone 1 towards zone 8 you therefore count down. Writing 0 45 90 … gives a wave travelling the other way, which is a perfectly good effect but not the one you asked for. To delay a zone by N degrees, write 360 − N.

This convention has never bitten anyone in the shipped library because across all of sessions/library the phase column only ever takes the values 0 and 180, which are symmetric under negation. The moment you reach for 45 or 90 it matters.

Anti-habituation jitter

A steady-state response to an absolutely fixed rhythm decays over a long hold: the system adapts to anything perfectly predictable. The counter is to make the rate wander slowly — enough that it never settles, little enough that it stays in band. The jitter column takes amp or amp:period_ms, where amp is in Hz and period is the full cycle (default 45 000 ms).

The two line types do genuinely different things, and this is the single most misunderstood column in the format:

LED lineAudio line
Scopeper channel-maskglobal — one setting for the whole session
What it movesthe flicker ratethe binaural detune, never the mod rate
Shapebipolar trianglebipolar sine
Amplitude limitclamped to 5 Hznone
Period limitunder 1000 ms is silently ignored — the previous value stays
 
# LED: wander the flicker rate +/- 0.4 Hz over a 60 s cycle
# time freq duty bright  R   G  B  mask env phase attack jitter
0      10   50    60    255 150 40  255   1     0      3  0.4:60000

# Audio: wander the binaural detune +/- 0.3 Hz over 53 s
# A time freq pan vol mod ch freqR wave duty env phase attack jitter
A   0   200   0  70   0   1   206    0   50   4     0      3  0.3:53000

Choosing non-commensurate periods for the two (60 s and 53 s above) keeps them from re-aligning into a slow super-rhythm of their own.

Three consequences of audio jitter being global. The last audio line in the file carrying a jitter column sets it for the whole session. A channel that sets no jitter column still wanders, if some other line turned it on. And a mono channel never wanders at all, because the offset is only ever added to the right carrier — if freqR is 0 there is nothing to move.

End a session by writing jitter explicitly back to 0. The global is not reset between sessions, so it leaks into whatever runs next.

If you want the isochronic pulse rate to wander, jitter is the wrong tool — it never touches mod. Modulate mod with a periodic glyph instead: ~9.6:10.4:40000.

Harmonic / octave stacking

One carrier at one pitch is a thin sound to sit inside for an hour. Running the same beat frequency on several octave-spaced carriers gives a far richer bed, and reinforces the frequency-following response at the beat rate rather than at any one carrier.

The detune is absolute, not proportional — you want the same Δf at every octave, so the beat is the same everywhere:

# A time freq pan vol mod ch freqR
A   0   100   0  70   0   1   106      # 6 Hz beat, fundamental
A   0   200   0  50   0   2   206      # 6 Hz beat, one octave up, quieter
A   0   400   0  35   0   3   406      # 6 Hz beat, two octaves up, quieter still

Doubling freqR along with freq would give you 6, 12 and 24 Hz beats — three different rhythms, not one reinforced one.

Attenuating the upper octaves by roughly 3–6 dB each matches how the ear weights them and keeps the stack from turning shrill. Note that vol is an absolute quantity on this device, not a share of a mix: every channel is scaled by a fixed 1/16 regardless of how many are running, so adding a fourth channel does not make the first three quieter. See the mixing model.

The breath layer

A slow envelope at about 0.1 Hz — six cycles a minute — laid over the top of whatever entrainment is running, on brightness or volume rather than on rate. It paces breathing without instructing it, and it is independent of the entrainment frequency underneath.

There is no dedicated breath parameter; you write it as an ordinary sine modulation on the bright or vol column. 0.1 Hz is a 10 000 ms period:

# LED brightness breathing 25 % to 65 % every 10 s, under a 10 Hz alpha flicker
# time freq duty bright            R   G   B  mask env
0      10   50   ~25:65:10000     255 150  40  255   1

# the same breath on an audio channel's volume
# A time freq pan vol             mod ch freqR
A   0   200   0  ~40:70:10000      0   1   206

Keep it fixed for the whole segment — a breath pacer that changes period is worse than none. Individual resonant frequencies sit between about 0.075 and 0.117 Hz (13.3 s to 8.5 s), so 10 s is a reasonable default and 4 s-in / 6 s-out is the usual calming asymmetry — though the ~ glyph is symmetric, so a true 4/6 split needs the saw glyphs / or \ instead.

Envelope shaping

The env column sets the shape of the pulse — the thing that is actually doing the entraining. It matters more than most authors expect, because a gate with sharp corners injects its own harmonics into the brain: an 8 Hz square gate is simultaneously driving 24 Hz at a third of the fundamental, which is beta content inside what you intended as an alpha session.

envShapeUses duty? Uses attack?Measured h3
0square gateyesno0.332
1raised sinenono0.001
2trianglenono0.110
3trapezoidyesyes0.321
4sine tremolo (bipolar, audio only)nono0.001

duty alongside env 1 or env 2 is a silent no-op. Neither shape reads it — the raised sine spans the whole cycle and the triangle is symmetric, so its on-fraction is always exactly 50 %. A duty modulation next to them is equally inert: the modulation engine will dutifully animate a value that nothing reads. If duty matters, use env 0 or env 3.

env 3 is the useful middle ground: a trapezoid keeps a real, settable duty cycle but takes the corners off with an attack ramp. Click-safe is ≥ 2 ms; the default is 3 ms on both paths. The stepped LED path caps attack at 60 ms — if you want an edge longer than that, what you are really asking for is env 1.

Defaults differ by line type, which catches people: an absent env column means 0 (square) on an LED line and 4 (tremolo) on an audio line, and an out-of-range value falls back the same way.

Colour, and why it is not decoration

At matched luminance, the colours at the ends of the spectrum drive a substantially stronger steady-state visual response than the ones in the middle. Measured by alternating pairs: amber/red 8.06 dB, blue/red 6.82 dB, green/lime 2.85 dB. The pattern is that any pair containing a red or a blue beats any pair without one — which is convenient, because the spectral extremes are also the complementary ones, so the strongest-driving pairs are the same pairs that work for antiphase.

For eyes-closed use there is a second, blunter consideration: the eyelid is a red filter. It passes roughly 14.5 % at 700 nm and under 3 % below 580 nm, so a blue bank behind a closed eyelid is doing a small fraction of the work the same bank does with eyes open. Bias closed-eye presets towards amber and red.

# time freq duty bright  R   G   B  mask env
0      10   50   55    255 150  40  255   1    # amber - good through eyelids
0      10   50   55     40 170 255  255   1    # cyan  - strong SSVEP, eyes open

Saturated red is a special case. Deep red flicker where R/(R+G+B) ≥ 0.8 is a recognised seizure trigger at rates above about 3 Hz, independent of brightness. The firmware does not check this. Keep saturated red below 3 Hz, or desaturate it.

What is not implemented

These were researched and specified for this project but do not exist in the firmware. They are listed here so you do not go hunting for a column that was never added, and so the gap between the research notes and the device is written down somewhere a session author will actually see it.

TechniqueStatusWhat you can do instead
Photosensitivity safety interlock Designed, deliberately not built. There is no safety_mode setting, no brightness clamp in the 15–25 Hz band and no saturated-red throttle anywhere in the firmware. Nothing automatic. The only gate that ships is a one-time notice in the browser, and a session played from the SD card never sees it. Author within the limits yourself.
Monaural beat mode No engine mode. There is no beat_mode field; the generator knows only “detuned carriers routed to separate ears”. Write it as two centre-panned channels with different carriers — they sum acoustically in each ear, which is what a monaural beat is. See the monaural page.
Dedicated breath LFO No breath parameter or envelope type. A ~ modulation on bright or vol, as in the breath layer above. Functionally equivalent; you just write the period yourself.
WAVE directive for traveling waves No directive that spreads a phase gradient across masked channels automatically. Write the per-zone phase values by hand, as in traveling waves. Eight lines instead of one.
AudioStrobe / SpectraStrobe emission Not implemented at all — no inaudible 18–20 kHz carrier is generated, so the device cannot drive third-party glasses that expect one. Nothing. Use the device's own LED outputs.
Periodic modulation on freqR and depth Partly implemented. Both accept > and * ramps, but a periodic glyph (~ ^ / \ _) is accepted by the tokenizer and then dropped: the parser logs a warning and holds the start value. Use a ramp, or step the value at successive timestamps.
