Measured results

Every number this project puts its name to, in one place, with the capture that produced it. Entrainment hardware is an unusually easy place to publish figures nobody checked; the point of this page is that each row below can be argued with.

How to read this. Figures come from the reports in reports/non_planned_reports/, taken on the ESP32-S3 build through the rig described under measuring what you built. Where a number is a hypothesis rather than a measurement it says so. Where something is still unknown it is listed at the end rather than omitted.

Audio-to-light synchronisation

The headline number, and the one that justifies the whole rig. A .ledc drives an LED gate and an audio gate at the same rate and phase, so the offset between the two recorded envelopes is the sync error.

Why the method is trustworthy

  • Edges are located by the peak of the derivative inside each cycle, not by a threshold crossing. The cell sits behind a capacitor into a high-impedance input, so the square droops and a fixed threshold is crossed repeatedly — that counted 42 edges where 27 existed. A drooping square still has exactly one sharp slope spike per edge.
  • All smoothing is a centred moving average. A causal filter folds its own group delay straight into the answer.
  • Running several rates in one session separates a real latency (constant time) from an envelope-shape artifact (constant phase). At 2/4/8 Hz the constant-latency model fit to 0.03 ms while constant-phase needed 39.9° of spread. It is a latency, unambiguously.

Per-edge scatter is 0.23–0.31 ms, and the two audio channels agree to 0.01 ms.

All twelve fall within −2.52…−3.53 ms — a 1.0 ms spread — independent of entry alignment and of whether the rate changed. Audio health across the run: 0 write errors, 0 short writes, 0 generator failures, fill average 910 µs of a 23 220 µs budget.

The −2.7 ms is deliberately not trimmed to zero. It cannot currently be separated into device-side offset versus measurement-chain bias: the audio path adds the codec's interpolation-filter group delay and its analog output stage, the light path adds LED turn-on and the cell's RC, and neither is independently known. Calibrating the constant away would bake one particular rig's bias into the firmware.

What the residual probably is hypothesis

Not confirmed by re-measurement — the arithmetic below is a prediction.

WS2812 bit timing makes a pixel 30.0 µs, so a 74-pixel strip takes 2.220 ms to clock out end to end. The analysis model treats the light path as a flat 2.5 ms regardless of where the sensor sits — but pixel i's bits reach the strip at i × 30 µs, so the model over-subtracts for any sensor near the head of the chain.

Independent support: the measured inter-eye offset of 0.33 ms is 0.33 ms ÷ 30.0 µs = exactly 11.0 pixels, which is what two sensors at different chain positions must look like. That number had been recorded for some time without an explanation. For two sensors near the head of the chain 11 pixels apart, the predicted residual is −2.34 ms against a measured −2.7 ms, leaving ~0.35 ms for the sensor's RC rise and recorder group delay — rather than the full 2.7 ms.

If that holds, the device-side A/V error is sub-millisecond and the residual is mostly a model and rig artifact.

Wave 7, the EEG contour, is a non-geometric single-cycle table with no closed-form spectrum. Measured h1…h6 = 1.000 / 0.500 / 0.331 / 0.221 / 0.140 / 0.091 — close to a 1/n series, harmonically rich as intended.

A measurement trap, recorded because it caught us twice. A naive wideband fit of brown noise over 300 Hz–9 kHz gives −4.81 dB/oct and looks like a defect. It is not — the slope is −6 over 60 Hz–3 kHz and only flattens above ~3 kHz, because everything is 24 dB down (below) and brown noise's high-frequency content lands a few int16 counts above the LSB, where the flat quantisation floor drags the fitted slope up. Fit a noise slope only where the signal is clear of both the analog and the quantisation floor, and state the band.

A sine at maximum on both controls reaches −27 dBFS: about 4 of the 16 bits go unused. The cause is a fixed 1/16 divisor (−24.1 dB) applied to every channel unconditionally, whatever the number actually playing — a hard overflow guarantee that cannot click. Across the 80 shipped sessions, counting the most simultaneously active channels each one reaches:

Simultaneous channelsSessionsHeadroom wasted
16124.1 dB

No shipped session uses more than 4 of the 16 channels, so the divisor is sized for a case that never occurs and every session loses at least 12 dB. The obvious fix — divide by the active count — is deliberately not applied: it would make every existing session up to 24 dB louder, and this is a head-worn device driving headphones whose user has set their amplifier for today's quiet output. See the mixing model.

The "sine" gate was returning a parabola, whose derivative discontinuity at the cycle boundary makes its harmonics fall as 1/n² instead of vanishing. The same defect existed on the LED side and the numbers prove it was literally the same shape — the LED path measured h2 0.286 / h3 0.145 before its fix, the audio path 0.251 / 0.112.

Why it matters therapeutically rather than cosmetically: an 8 Hz alpha gate with h2 = 0.25 is simultaneously driving 16 Hz at a quarter of the fundamental — beta content inside what the author intended as an alpha session.

What the rig itself contributes

A measurement is only as good as its instrument, so the instrument was measured too.

PropertyFigure
Sensor signal-to-noise +45.2 dB (ch1) / +41.8 dB (ch2), against the 50 Hz line at −87.6 dBFS measured with the LEDs dark
Inter-eye offset A constant 0.33 ms, reproducible across runs — the serial LED update order, not a fault. See the residual hypothesis.
LED-to-audio crosstalk, ground loop +44 dB — a ground loop through the shared USB ground, not a device fault
LED-to-audio crosstalk, isolated +16.9 dB with the device on an isolated USB adapter, i.e. −39.6 dB below the audio carrier. Not worth chasing.

The input impedance changes the answer. On a line input (~20 kΩ) the cell's series capacitor differentiates (corner ~80 Hz): the capture shows edge spikes instead of a brightness envelope and the harmonic ladder flattens to 1 / 0.91 / 0.86 / 0.82 / 0.79. On a high-impedance instrument input the same signal gives 1 / 0.33 / 0.20 / 0.14 / 0.11, matching a 50 % square to within 0.01. Amplitude and brightness grading are meaningless on the wrong input.

Mains hum is a red herring at 10 Hz: the 5th harmonic of a 10 Hz flicker lands exactly on 50 Hz. Measure the 50 Hz line with the LEDs dark before blaming it.

Still open

What it would take to close the −2.7 ms residual honestly:

TermMagnitudeHow to pin it
Strip serialisation0 … 2.22 ms Replace the flat 2.5 ms with rmt_start + k × 30 µs, taking the sensor's pixel index k as a measurement input. Model change only — no hardware.
Each sensor's pixel index k— The rig builder knows it, or light the zones in a known order and read the map off one capture.
DAC + analog group delayunknown, ~0.1–1 ms? Toggle a spare GPIO at the generator block boundary into a free recorder input, so the recorder holds the digital event and the analog audio on one timebase.
Recorder inter-channel skewexpected < 10 µs Y-split one signal into an audio input and a light input; one capture.
Sensor RC rise~0.1 ms? Hard-step the LED and measure 10–90 % rise.

The strip term is the only one large enough to explain the residual on its own, and the only one fixable without touching the rig.
