Offline playback from the SD card

What you are trying to achieve: start a session and close the laptop. Tones and flicker already run entirely on the device — this page is about the two things that normally need a browser, spoken narration and background music, and how to move them onto a microSD card so nothing has to stay connected.

Why some sessions need the browser

Spoken lines in a session are not synthesised on the device — there is no text-to-speech engine in the firmware. Normally the browser speaks them, mixes the result with the background track into one audio stream, and feeds that stream to the device in real time for the entire session. It works, but it means the browser is part of the playback chain: close it, lock the screen, or walk out of WiFi range and the audio stops.

The fix is to pre-render every phrase once and store it on the card. After that the device opens the files itself and mixes speech, background and tones on its own. The browser becomes a remote control you can put down.

Offline playback needs a device whose firmware was built with SD support, and the card wired up. The giveaway in the UI is the SD Card group on the Settings tab: it only appears if the firmware has the feature compiled in. If that group is missing, this page does not apply to your build. Check the sdcard chip on the Diagnostics tab to see whether a card actually mounted at boot.

Prepare the card

  1. Format a microSD card as a single FAT32 partition. Capacity is not a constraint — the content is small.
  2. Insert it and power-cycle the device. The card is mounted at boot; the firmware will never format it for you, and a card that fails to mount is reported rather than reformatted.
  3. Confirm the sdcard chip on Diagnostics is green.

A missing or unreadable card is harmless. The firmware treats it as removable media throughout: it never blocks startup, never interrupts a running session, and every path that wants the card checks first and falls back to the network or the browser instead.

Sync the speech library

The card holds a library of phrases, not a mixed recording per session. One file per unique phrase, shared across every session that uses it, so adding a session costs almost nothing and re-syncing only uploads what is missing.

  1. Make sure the browser you are using has internet access — the phrases that are not already cached have to be synthesised now.
  2. Open Settings and scroll to Browser preferences → Offline speech (preload).
  3. Check Speech (TTS) engine first. Puter.js (browser, neural — no key) runs in your browser and may pop up a Puter sign-in; Google (proxied via the device) needs the device to be online instead. The choice is stored in this browser only, and it changes the voice — so decide before you fill the card.
  4. Press ⇪ Sync speech to SD card.
  5. Watch the status line underneath. It reports the card (Card "SD32G" — 14422 MB free. Scanning sessions…), then progress (Syncing… 18/42 (6 uploaded, 12 already there)), then a summary (✓ Card ready — 42 phrase(s) available offline (6 uploaded, 36 already present).).

Re-running it is cheap: phrases already on the card are skipped without being re-synthesised, and phrases already in the browser's own cache upload without hitting the speech engine at all. Run it again whenever you add sessions, and always run it again if you change the speech engine — a different engine means different audio for the same words.

If some phrases fail you get Finished with 3 failure(s)… Sessions with missing phrases still play via the browser. That is the honest outcome: those particular sessions lose their offline capability, nothing else breaks.

The neighbouring button does something different

⤓ Preload all speech, just above, caches every phrase in this browser rather than on the device. That is for playing sessions from a laptop with no internet — useful on the road — but the browser is still driving playback. For "close the laptop", you want ⇪ Sync speech to SD card.

Play a session offline

There is no offline mode to switch on. Play the session as usual from Home, and the page decides:

  1. Press ▶ PLAY Config.
  2. If every spoken phrase the session needs is on the card, the status says Playing offline (speech from SD card). The device is now self-sufficient — close the tab, close the laptop, walk away.
  3. If anything is missing, or the card is not mounted, or the device cannot be asked, you get Playing (speech merged into background) instead and the browser streams the session as normal. Leave it open.

That fallback is deliberate and it errs on the side of working: a session that plays with the laptop open beats one that half-plays without it. The check is all-or-nothing, though — a single un-synced phrase sends the whole session back to the browser path.

The flicker runs either way. Offline playback is not a lesser mode: the LED timeline executes on the device regardless of whether a browser is attached, and the browser-side safety notice cannot appear if no browser is attached. If someone else might start or be in front of the device, make sure they have read the safety section on the overview page first.

Background music from the card

Background tracks live in a /bg/ directory on the card and are referenced from a session by a sdcard:// URL, for example BG  sdcard://bg/river.wav  0  30. Because the device reads them directly, a session with card-based background needs no browser and no internet.

The simplest way to load music is to pull the card out and copy files onto it from a computer — the sync button handles speech, not your music library. Audio must be 16-bit PCM WAV (or MP3 on builds with MP3 support) at 44.1 kHz or 22.05 kHz, mono or stereo; other sample rates are rejected with a log message you will see on the Diagnostics tab.

The card's layout

PathContents
/speech/sp_<hash>.wav One file per unique spoken phrase. The name is derived from a hash of the phrase itself, which is why there is no index file to keep in sync and why sessions do not have to be changed to use the card.
/bg/<name>.wav Background tracks, referenced as sdcard://bg/<name>.wav.

The hashed speech filenames are not meant to be readable, and you should not rename them — the device works out which file a line needs by recomputing the hash, so a renamed file is simply never found. Deleting one is safe: the session falls back to the browser path, and the next sync puts it back.

Managing files over WiFi

The device exposes the card over HTTP, which is what the sync button uses and what you can use by hand from a terminal:

RequestDoes
GET /api/sd Lists the card's files (root, speech/ and bg/) with sizes, plus total and free space and the card's name. Reports mounted: false when there is no card.
GET /api/sd/<name>Downloads a file.
PUT /api/sd/<name> Uploads a file, streamed straight to the card. One directory level is allowed (bg/river.wav is fine), names are restricted to letters, digits, ., _ and -, and a single file may not exceed 64 MB.
DELETE /api/sd/<name>Removes a file.

These endpoints have no authentication, like the rest of the device's API. Anyone who can reach the device on the network can read, replace or delete files on the card. Treat the device as a trusted-network appliance and do not expose it to the internet.
