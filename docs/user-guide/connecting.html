Connecting to the device

What you are trying to achieve: get the device's control page open in a browser. The whole interface is served by the device itself, so there is nothing to install — you just need to reach it.

The short answer

Type http://esp32-ave.local into a browser on the same network as the device. That name works whether the device joined your WiFi or is running its own, so it is the one address worth remembering.

Plain http, not https — the device does not do TLS. Browsers sometimes "helpfully" upgrade a bare hostname to https and then report that the site is unreachable; typing the http:// prefix explicitly avoids that.

First run: there is no WiFi configured yet

A device that has no network stored — or that cannot join the one it has — brings up its own access point instead. This is also the recovery path for "I moved house and the old SSID is gone".

  1. Power the device on and give it a few seconds.
  2. On your phone or laptop, join the WiFi network ESP32-AVE-Setup. The WPA2 password is entrain123.
  3. Browse to http://192.168.4.1 (or http://esp32-ave.local, which also works here).
  4. Open the Settings tab and find the WiFi group. Fill in WiFi SSID and WiFi password.
  5. Press Save & Reboot. The device restarts and joins your network — which also means it drops its own access point, so your phone will fall back to whatever it was on before.
  6. Reconnect your phone or laptop to your normal WiFi and browse to http://esp32-ave.local.
The ESP32 is 2.4 GHz only. It cannot see a 5 GHz network at all. If your router publishes both bands under one name this is usually fine; if you have a separate 5 GHz SSID, do not give the device that one.

Finding the device on your network

Once it joins your WiFi, your router hands the device a DHCP address that you cannot predict and that can change. Rather than hunting for it, the device advertises itself over mDNS, so a name always works.

SituationAddressNotes
Joined your WiFi (normal use) http://esp32-ave.local Works regardless of which IP the router gave it.
Running its own access point http://192.168.4.1 Fixed address. esp32-ave.local resolves here too.
mDNS blocked or unsupported http://<device IP> Read the IP from your router's client list, or from the serial log at boot if you have a cable attached.

The hostname is configurable: Settings → WiFi → mDNS hostname. The default is esp32-ave, giving esp32-ave.local. Only letters, digits and hyphens survive — anything else is stripped — and the change needs a reboot.

mDNS (.local) works out of the box on macOS, iOS, modern Windows and most Linux desktops running Avahi. Some corporate and guest networks block the multicast traffic it depends on; some Android versions are unreliable about it. If the name does not resolve, nothing is wrong with the device — use the IP.

Forcing setup mode on purpose

If the configured network is unreachable and you want to change the credentials, you do not have to wait for the join to time out:

  1. Hold the device's hardware button down.
  2. While still holding it, power the device on (or press reset).
  3. It boots straight into access-point setup mode, skipping the attempt to join your WiFi, and logs that it did so.
  4. Join ESP32-AVE-Setup and configure it as in the first-run steps above.

This is the same momentary button used during a session (short press logs a state snapshot, three-second hold stops everything). It is the GPIO named by Button GPIO in Settings → Controls; if that is set to -1 the button is disabled and this trick is not available.

In the field: use a phone hotspot

Away from home, the tidiest arrangement is to make your phone the network. The device joins the hotspot, and because you are on the same hotspot you can reach it by name and the device gets internet through your phone — which is what speech synthesis, the Generator's Community session browser and http:// background audio all need.

  1. Turn on your phone's hotspot. On an iPhone 12 or newer, also turn on Maximize Compatibility so the hotspot runs 2.4 GHz.
  2. Set that SSID and password in Settings → WiFi, then Save & Reboot.
  3. Browse to http://esp32-ave.local from the same phone.

The device's own access point has no internet behind it. Everything local works there — playing sessions, live control, settings, diagnostics, firmware updates — but anything that reaches out to the internet does not. If you need speech or community sessions, be on a real network or a hotspot.

One browser tab is enough

The device answers HTTP on a single task with a budget of seven sockets, three of which are reserved internally. The web page is written to respect that: all of its traffic is funnelled through one gate that allows at most two requests in flight at a time, and its background pollers only schedule the next request after the previous one finishes.

That budget is per page, though. Open the UI in four tabs and you have four independent pollers competing for the same handful of sockets and for your browser's six-connections-per-host limit, which is exactly how the interface ends up looking frozen while the device is perfectly healthy. Keep one tab open, and close stale ones. See troubleshooting for what that failure looks like and how to confirm it.
